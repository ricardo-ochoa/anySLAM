1 · Qué es Docker

Tu entorno, empaquetado

Docker empaqueta una aplicación con todo lo que necesita y la ejecuta aislada del resto del sistema. 

docker build -t ros2-docker-template:1.0 .     # Dockerfile → imagen
docker run --rm -it ros2-docker-template:1.0    # imagen → contenedor
1 · Qué es Docker

Cómo funciona por dentro

El comando docker solo da órdenes. Quien hace el trabajo es el daemon, que administra cuatro tipos de objetos.

Ojo con el grupo docker — quien puede hablar con docker.sock tiene, en la práctica, permisos de root en esa máquina.
1 · Por qué se usa

Por qué en robótica

Reproducible

El mismo entorno en tu laptop, en CI y en el robot.

Sin conflictos

Humble y Jazzy conviven en la misma máquina, cada uno en su contenedor.

Onboarding rápido

Clonar y levantar en minutos, no instalar durante un día.

Multiplataforma

Una imagen para amd64 (laptop) y arm64 (Jetson, Raspberry Pi).

Lo que no resuelve — el kernel es el del host: drivers, tiempo real y permisos de hardware se configuran en el robot, no en la imagen.

3 · Multi-arquitectura

El sistema operativo no es la arquitectura

Para Docker no importa si trabajas en Windows, Mac o Ubuntu, sino el procesador: linux/amd64 o linux/arm64.

AMD64 · x86_64

  • PC con Windows o Ubuntu
  • Mac con Intel
  • Servidores de CI

ARM64

  • Mac con Apple Silicon
  • Raspberry Pi con SO de 64 bits
  • NVIDIA Jetson
docker image inspect ros2-docker-template:1.0 --format '{{.Os}}/{{.Architecture}}'
# linux/amd64  → sirve en la PC, no en la Jetson ("exec format error")
3 · Multi-arquitectura

Un tag, varias arquitecturas

Una imagen multi-arquitectura guarda bajo el mismo nombre una variante por procesador.

ghcr.io/ricardo-ochoa/ros2-docker-template:1.0-multiarch
linux/amd64
linux/arm64
PC Ubuntu · Windows · Mac Intel
Jetson · Raspberry Pi · Mac Apple Silicon
El mismo docker pull en cualquier máquina: Docker detecta la arquitectura y descarga la variante correcta.
3 · Multi-arquitectura

Cómo se construye: Buildx

# 1. Una sola vez en Ubuntu: emulación para construir otras arquitecturas
docker run --privileged --rm tonistiigi/binfmt --install all

# 2. Una sola vez: builder multiplataforma
docker buildx create --name multiarch-builder --driver docker-container --use --bootstrap

# 3. Construir ambas y publicarlas bajo el mismo tag
docker buildx build --platform linux/amd64,linux/arm64 \
  -t ghcr.io/ricardo-ochoa/ros2-docker-template:1.0-multiarch --push .

# 4. Verificar qué variantes contiene
docker buildx imagetools inspect ghcr.io/ricardo-ochoa/ros2-docker-template:1.0-multiarch
Dos detalles — sin --push el resultado se queda en el caché del builder, y construir ARM64 emulado es lento. En la clase 8 esto lo hace CI automáticamente.
4 · Las piezas

En Ubuntu usamos Docker Engine

Docker Engine

  • Corre nativo sobre el kernel del host
  • --network host y --device funcionan directo
  • Es lo mismo que corre en el robot

Docker Desktop en Linux

  • Corre dentro de una VM, también en Ubuntu
  • Red host, USB y GPU no se comportan igual
  • Licencia de pago en empresas grandes
# ¿tienes ambos? revisa cuál está activo
docker context ls
docker context use default    # Engine nativo
4 · Las piezas

GHCR es parte de GitHub Packages

GitHub tiene un registro por tipo de paquete. El de imágenes Docker vive en ghcr.io.

Por qué lo usamos — mismos usuarios, permisos y Actions que el repo. Las imágenes públicas son gratis; las privadas usan la cuota del plan.
4 · Las piezas

Docker Hub y GHCR en el mismo flujo

Nuestro Dockerfile

3
GHCR
