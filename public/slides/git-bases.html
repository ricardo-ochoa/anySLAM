1 · Qué es Git

Una historia de snapshots

Git guarda tu proyecto como una cadena de fotografías llamadas commits. Cada una apunta a la anterior.

git log --oneline
e7d5b38 (HEAD -> main) Publica v1.0
c41e90a Corrige bug
8b27d4e Agrega sensor
3f9a1c2 Primer commit
2 · Staging

El staging: tu sala de espera

Primero eliges qué cambios entran con git add. Después los guardas con git commit.

Para qué sirve — te deja armar commits pequeños y con sentido aunque hayas tocado muchos archivos. Revisa el estado con git status.

Cómo viajan los cambios

3 · El ciclo de trabajo

Editar, preparar, guardar

git init                          # crea el repositorio (la carpeta .git)
git status                        # ¿en qué estado está cada archivo?
git add robot.py                 # Untracked / Modified → Staged
git commit -m "Agrega robot"    # Staged → Committed
git log --oneline                # historial de commits
4 · Ramas

Una rama es un apuntador

git switch -c feature             # crea la rama y te mueve a ella
git commit -m "Agrega sensor"    # solo avanza feature
4 · Ramas

Conectar cambios entre ramas

En el diagrama — feature y hotfix nacen de main y regresan con git merge. El commit final (rosa) junta las historias.
4 · Conflictos

Cuando dos ramas chocan

git switch -c rama-conflicto
echo "hola desde la rama" > archivo-prueba.txt
git add .
git commit -am "Cambio en rama-conflicto"

git switch main
echo "hola desde main" > archivo-prueba.txt
git add .
git commit -am "Cambio en main"

git merge rama-conflicto
# CONFLICT (content): Merge conflict in archivo-prueba.txt
<<<<<<< HEAD              # tu versión (main)
hola desde main
=======
hola desde la rama        # versión de la otra rama
>>>>>>> rama-conflicto

# borra las marcas, deja el texto final y:
git add archivo-prueba.txt
git commit -m "Resuelvo conflicto"
git log --oneline --graph --all   # o: git merge --abort
5 · Remotos

Compartir con origin y GitHub

git clone https://github.com/usuario/proyecto.git   # copia el remoto a tu laptop
git push -u origin main                              # sube tus commits
git pull                                              # trae los de tus compañeros
6 · Deshacer

Deshacer cambios

git revert <id> seguro

Crea un commit nuevo que deshace los cambios de un commit específico. Es lo indicado en repositorios compartidos.

git reset <id> último recurso

Mueve HEAD a un commit anterior y saca los cambios del historial, como si nunca hubieran ocurrido.

Modo de resetHEADStagingDirectorio de trabajoEn una frase
--softSe mueveSe queda igualSe queda igualDeshace el commit; los cambios siguen en staging
--mixed (por defecto)Se mueveSe vacíaSe queda igualDeshace el commit y saca los archivos del staging

Para inspeccionar — git show <id|tag> muestra el detalle de un commit o de un tag, y también combinaciones de ramas y archivos.
Flujo de equipo

Ramas cortas, integración por PR

git switch -c feature/login-google
git push -u origin feature/login-google
# Pull Request → revisión + CI → merge a main
git switch main && git pull
git branch -d feature/login-google

Reglas del flujo

  • main siempre estable y desplegable
  • Ramas cortas con nombre descriptivo: feature/…, fix/…
  • Todo entra por Pull Request (revisión y CI) y después la rama se borra
Resumen

Lo que te llevas

Staging

git add elige qué entra. git commit lo guarda en la historia.

Ramas

Una rama es solo un apuntador.git merge une el trabajo.

Remotos

origin es otra copia del repo. push sube, pull trae.

Commits pequeños, mensajes claros y ramas de vida corta.
