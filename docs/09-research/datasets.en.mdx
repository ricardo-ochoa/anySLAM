## External datasets

### SCAND — Socially Compliant Navigation Dataset

A navigation dataset with human demonstrations across diverse scenarios. The team uses it to
train the navigation architecture, aiming for robustness across different human navigation
behaviours.

**Reference:** Karnan et al. (2022), [arXiv:2203.15041](https://arxiv.org/abs/2203.15041)

### PushT

A manipulation environment used as an initial test bench, from the Diffusion Policy work (Chi et
al., 2023). It is not a project dataset but a validation environment.

## Trajectory datasets — ARKit

[`FLOWMAS-ANYmal`](https://github.com/carloAdr1/FLOWMAS-ANYmal) trains by default on a custom
dataset of **ARKit** captures, stored in **Zarr** format.

| Aspect | Value |
| --- | --- |
| Format | Zarr (`data/arkit_dataset_test.zarr`) |
| Contents | `rgb`, `depth`, `poses`, `actions` |
| Normalisation | Poses, actions and depth are already normalised in the file |
| Conversion | `utils/arkit_to_zarr.py` |

ARKit is Apple's augmented-reality framework, which implies captures are made with an iOS device
carrying a depth sensor. **Still to confirm**: which device, who records them, and where they are
archived.

## Preprocessing tool

The [ICRA 2025 poster](/en/docs/09-research/papers) mentions a custom preprocessing tool,
visualising the camera image alongside its Scan Context representation.

The current repository ships `utils/arkit_to_zarr.py`, but that converts ARKit captures, not
point clouds into Scan Context. It may be a different tool, or that part may have been dropped
when moving from sparse cloud to dense depth. To be confirmed.
